# 私密写真单列画廊设计

## 目标

只优化 APP 套餐详情的“私密写真”Tab，将现有三个文字写真字段呈现为适合手机阅读的单列竖版画廊卡片，并为后续生图结果接入预留稳定的图片展示区域。

## 范围

- 只修改 `src/APP/ItemDetail.vue` 及其针对私密写真 Tab 的源代码回归测试。
- 不修改“特色玩法”“顾客评价”、顶部套餐信息、Tab 切换、底部下单栏或数据解析逻辑。
- 不新增或改变 MVU 字段；继续读取 `image1`、`image2`、`image3`。

## 数据兼容

当前 `image1`、`image2`、`image3` 是文字提示词。组件保留这些文字并显示为“待生成”内容。

如果字段未来变成图片 URL 或 data URL，则同一张卡片自动切换为图片展示；图片下方仍保留标签和提示词/说明区域。这样生图数据可以先复用现有字段，不要求本次改动同步后端或角色卡结构。

## 视觉与布局

- 私密写真区域使用独立的 `private-photo-panel`，保留单列布局。
- 每张卡片包含标签栏、竖版媒体区域和文字说明区。
- 图片媒体区使用 `aspect-ratio: 4 / 5`、`object-fit: cover` 和统一圆角。
- 文字提示词使用左上对齐、可换行和自适应高度，避免固定高度裁切长文本。
- 当前没有图片时显示轻量的相机图标/“待生成”状态，不伪造图片资源。
- 私密写真区域末尾增加安全留白，避免最后一张卡片贴近固定下单栏。

## 验收标准

1. 现有文字 `image1/2/3` 均仍能完整显示，长文本不被固定高度裁切。
2. 图片 URL 或 data URL 能在同一张卡片的媒体区域显示，并保持竖版比例。
3. 私密写真卡片只占一列，不产生横向滚动。
4. 详情页现有滚动容器、Tab 切换和下单操作保持不变。
5. APP 源码测试和完整构建通过，并在真实 Tavern iframe 中检查私密写真页的视觉结构与滚动。
