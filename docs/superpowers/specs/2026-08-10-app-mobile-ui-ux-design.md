# APP 移动端 UI/UX 统一优化设计

## 目标

在不改变现有业务逻辑、数据结构和路由的前提下，统一美人团 APP 的移动端视觉与触控体验，降低页面之间的认知切换成本，并提升阅读、浏览、下单和设置操作的可达性。

## 设计方向

采用“统一设计层 + 页面重点微调”的渐进式方案：保留现有黄白品牌与信息架构，通过全局设计令牌、移动端触控规范和页面级间距/层级调整，改善整个 APP，而不是重做某一个页面。

## 适用页面

- 首页：公告、分类入口、搜索和特色玩法的层级与密度。
- 发现：店铺卡片、导入入口、删除操作和空状态。
- 店铺/套餐详情：返回导航、标签、内容卡片、固定下单栏和备注弹窗。
- 服务、历史、我的：信息卡片、折叠区、空状态和操作按钮。
- 正文：保留现有滚动与流式自动跟随逻辑，统一阅读卡片、输入区和快捷导航。
- 调试台：只共享基础触控和可访问性规则，不改变调试工具的信息密度与功能。

## 统一设计规则

### 视觉层级

- 保留 `--accent-primary` 黄色作为主要行动色，避免新增颜色体系。
- 统一卡片的边框、圆角和阴影层级，减少页面之间不一致的视觉噪声。
- 通过标题、辅助说明、正文和状态文本的字号/颜色/行高建立明确层级。
- 移动端正文和长文本使用更舒适的左右留白与行高，避免内容贴边或过密。

### 触控与反馈

- 主要按钮、图标按钮、导航项的可操作区域保持至少 44px，重要行动按钮优先 48px。
- 使用 `touch-action: manipulation` 和按下态反馈降低触控迟滞感。
- 增加统一的 `:focus-visible` 样式，保留键盘和辅助技术的定位线索。
- 不为触摸设备依赖 hover；按下反馈应即时、克制，并支持 `prefers-reduced-motion`。

### 页面结构

- 顶部栏统一标题、返回/操作按钮的尺寸、间距和单行溢出策略。
- 底部导航统一高度、激活态和安全区留白，确保窄屏下标签仍可读。
- 内容区在移动端使用稳定的 12–16px 外边距和一致的区块间距。
- 固定底部操作区与内容保持清晰分层，不遮挡最后一段内容。

## 约束与非目标

- 不改 API、酒馆变量、数据解析、生成流程和路由行为。
- 不新增第三方依赖，不引入 `vh`/`dvh` 作为 iframe 高度方案。
- 保留现有桌面端布局，只在必要处通过现有响应式规则优化移动端。
- 保留工作区中与本任务无关的已有修改和构建噪声。

## 验证标准

- 现有 APP 源码测试继续通过，新增的源代码回归测试覆盖统一触控规则和关键移动端布局标记。
- `pnpm build` 成功，并生成最新的 `dist/APP/index.html`。
- 使用移动端宽度检查首页、发现、详情、历史、服务、我的和正文的横向溢出、按钮触控尺寸、底部导航遮挡和弹窗可滚动性。
- 对真实酒馆 iframe 的检查与本地构建结果分开报告；无法加载目标 APP iframe 时不将静态构建结果等同于实机验证。
