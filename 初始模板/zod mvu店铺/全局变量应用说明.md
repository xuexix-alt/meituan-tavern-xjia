## 1. 概念与用途

### 1.1 什么是全局变量

在ZOD MVU项目中，**全局变量**是定义在Schema顶层的变量，所有角色和聊天层都可以读取、修改和存储这些变量。它们代表了**整个游戏世界共享的状态信息**。

### 1.2 全局变量 vs 角色变量

| 特征 | 全局变量 | 角色变量 |
|------|----------|----------|
| **作用范围** | 整个游戏世界 | 单个角色 |
| **访问权限** | 所有角色/系统 | 通常只有相关角色 |
| **生命周期** | 贯穿整个游戏 | 跟随角色存在 |
| **修改权限** | 任何人都可以修改 | 通常受限修改 |
| **典型用途** | 时间、地点、事件 | 好感度、状态、装备 |

### 1.3 全局变量的典型用途

#### 📅 时间系统
- 游戏天数
- 当前时辰
- 经过小时数
- 日期和时间

#### 🌍 世界状态
- 当前地点
- 天气状况
- 季节变化
- 环境描述

#### 📊 进度追踪
- 主线事件进度
- 支线任务状态
- 成就完成情况
- 隐藏要素收集

#### 🔢 统计计数
- 击败敌人数量
- 完成任务数量
- 收集物品数量
- 互动次数统计

#### 🎭 系统状态
- 游戏模式
- 难度级别
- 特殊标志
- 解锁状态

## 2. 设计原则

### 2.1 顶层优先原则

全局变量应该直接定义在Schema顶层，而不是嵌套在特定角色下：

```javascript
// ✅ 推荐：顶层定义
export const Schema = z.object({
  // 全局变量在顶层
  世界: z.object({...}),
  时间系统: z.object({...}),
  事件状态: z.record(...),

  // 角色变量在独立命名空间
  角色A: z.object({...}),
  角色B: z.object({...})
}).strict();

// ❌ 错误：嵌套在角色下
export const Schema = z.object({
  角色A: z.object({
    // 错误：这里应该是全局变量
    世界时间: z.string(),
  })
}).strict();
```

### 2.2 命名规范原则

- **清晰明确**：变量名应该能直观表达含义
- **分层命名**：使用`.`分层，如`世界.当前时间`
- **统一前缀**：同类变量使用相同前缀
- **避免缩写**：除非是约定俗成的缩写

### 2.3 类型安全原则

所有全局变量都必须通过Zod定义类型，确保：
- 正确的类型转换
- 合理的范围限制
- 自动的数据修正
- 幂等性保证

### 2.4 独立更新原则

全局变量的更新应该**独立于特定角色**，即使没有特定角色在场，也可以修改全局状态：

```javascript
// ✅ 正确：独立更新
{ "op": "replace", "path": "/世界/当前时间", "value": "新时间" }

// ❌ 错误：依赖角色存在
{ "op": "replace", "path": "/角色A/世界时间", "value": "新时间" }
```

## 3. 完整实现方案

### 3.1 Schema定义（变量结构.js）

```javascript
import { registerMvuSchema } from 'https://testingcf.jsdelivr.net/gh/StageDog/tavern_resource/dist/util/mvu_zod.js';

export const Schema = z.object({
  // ===== 全局变量区 =====
  // 世界状态
  世界: z.object({
    当前时间: z.string(),  // 格式：YYYY年MM月DD日 上午/下午 HH:MM
    当前地点: z.string(),
    天气: z.string(),
    季节: z.enum(["春季", "夏季", "秋季", "冬季"]).catch("春季"),
    昼夜: z.enum(["黎明", "清晨", "上午", "中午", "下午", "傍晚", "夜晚", "深夜"]).catch("上午")
  }).strict(),

  // 时间系统
  时间系统: z.object({
    游戏天数: z.coerce.number().int().nonnegative(),  // 从1开始
    当前时辰: z.enum(["深夜", "凌晨", "清晨", "上午", "正午", "下午", "傍晚", "夜晚"]).catch("上午"),
    经过小时数: z.coerce.number().transform(v => _.clamp(v, 0, 24)),  // 0-24
    总游戏时长: z.coerce.number().nonnegative()  // 以小时为单位
  }).strict(),

  // 全局事件状态
  事件状态: z.record(
    z.coerce.boolean()
  ).prefault({}),  // { "主线_初遇": true, "支线_救援": false, ... }

  // 全局计数器
  计数器: z.record(
    z.coerce.number().int().nonnegative()
  ).prefault({}),  // { "击败_敌人": 5, "完成_任务": 3, ... }

  // 全局设置
  设置: z.object({
    游戏模式: z.enum(["简单", "普通", "困难", "专家"]).catch("普通"),
    语言偏好: z.string().default("中文"),
    音效开关: z.coerce.boolean().default(true),
    自动保存: z.coerce.boolean().default(true)
  }).strict(),

  // ===== 角色变量区 =====
  主角: z.object({
    姓名: z.string(),
    等级: z.coerce.number().int().positive(),
    经验值: z.coerce.number().nonnegative(),
    当前位置: z.string(),
    好感度: z.record(
      z.coerce.number().transform(v => _.clamp(v, 0, 100))
    ).prefault({})  // { "角色A": 50, "角色B": 30, ... }
  }).strict(),

  角色A: z.object({
    是否相遇: z.coerce.boolean(),
    好感度: z.coerce.number().transform(v => _.clamp(v, -100, 100)),
    当前状态: z.string(),
    位置: z.string()
  }).strict(),

  角色B: z.object({
    是否相遇: z.coerce.boolean(),
    好感度: z.coerce.number().transform(v => _.clamp(v, -100, 100)),
    当前状态: z.string(),
    位置: z.string()
  }).strict()

}).strict();

$(() => {
  registerMvuSchema(Schema);
})
```

### 3.3 更新规则（变量更新规则.yaml）

```yaml
---
变量更新规则:
  # ===== 全局变量规则 =====
  世界:
    当前时间:
      format: YYYY年MM月DD日 上午/下午 HH:MM
      check:
        - 每次事件推进、休息、旅行后自然更新
        - 保持时间流逝的合理性（1次交互≈1-3小时）
        - 可通过特殊事件快速推进（睡眠8小时、传送等）
        - 跨天时日期+1

    当前地点:
      check:
        - 角色移动、传送、旅行时立即更新
        - 应描述具体场所（房间名、区域名）
        - 跨场景移动需说明移动过程和距离
        - 地点变更可能影响天气和环境

    天气:
      check:
        - 长时间场景变化时更新（跨天、跨区域）
        - 特殊事件可临时改变天气（魔法、灾害等）
        - 保持与季节和地理位置的合理性
        - 极端天气应持续至少2-3小时

    季节:
      check:
        - 游戏天数每增加30天自动更新
        - 可通过特殊事件人工调整（时间魔法等）
        - 季节变化影响天气、植被、活动类型
        - 季节变更应触发特殊事件或描述

    昼夜:
      type: enum
      check:
        - 根据当前时辰自动更新
        - 影响NPC作息和可执行行动
        - 夜晚可能有特殊事件或危险

  时间系统:
    游戏天数:
      type: number
      range: 1~9999
      check:
        - 每经过24小时+1
        - 可通过睡眠、昏迷等特殊事件调整
        - 记录重要日期和纪念日
        - 某些事件可能需要等待特定天数

    当前时辰:
      type: enum
      check:
        - 根据经过小时数自动更新
        - 0-5: "深夜", 6-8: "凌晨", 9-11: "清晨", 12: "正午"
        - 13-17: "下午", 18-20: "傍晚", 21-22: "夜晚", 23: "深夜"
        - 影响角色作息和可用行动

    经过小时数:
      type: number
      range: 0~24
      check:
        - 每次交互推进1~3小时（简单对话1小时，探索2小时，战斗3小时）
        - 重要事件可推进更多（长途旅行、工作等）
        - 满24自动归零并+1游戏天数
        - 影响角色疲劳和需求

    总游戏时长:
      type: number
      range: 0~99999
      check:
        - 每次交互累加实际游戏时间
        - 用于统计和成就系统
        - 不会重置，除非特殊事件

  事件状态:
    type: |-
      {
        [事件名: string]: boolean;  // true=已完成, false=未完成
      }
    check:
      - 任何角色或系统都可以标记事件状态
      - 一旦标记为true，通常不可逆（除非特殊规则明确说明）
      - 命名规范：
        * 主线_xxx：主线剧情事件
        * 支线_xxx：支线任务事件
        * 隐藏_xxx：隐藏内容或彩蛋
        * 成就_xxx：成就类事件
        * 收集_xxx：收集类事件
      - 事件完成可能解锁新区域、新角色或新功能
      - 部分事件可能有前置条件

  计数器:
    type: |-
      {
        [计数器名: string]: number;  // 各种数值统计
      }
    check:
      - 任何角色或系统都可以修改计数器
      - 用于统计成就、解锁条件、进度等
      - 命名规范：
        * 击败_xxx：战斗相关统计
        * 完成_xxx：任务完成统计
        * 收集_xxx：物品收集统计
        * 遇到_xxx：NPC遭遇统计
        * 交谈_xxx：对话相关统计
        * 使用_xxx：道具使用统计
      - 某些计数器达到特定值会触发事件或解锁内容
      - 计数器通常只增不减（除非特殊规则）

  设置:
    游戏模式:
      type: enum
      check:
        - 影响游戏难度和机制
        - 简单：降低敌人强度，减少资源消耗
        - 普通：标准游戏体验
        - 困难：增加敌人强度，提高资源需求
        - 专家：极限挑战模式
        - 模式变更可能影响成就计算

    音效开关:
      type: boolean
      check:
        - 控制游戏音效播放
        - 不影响游戏逻辑，仅影响体验
        - 可随时切换

    自动保存:
      type: boolean
      check:
        - 控制是否自动保存游戏进度
        - 开启时每次重要操作后自动保存
        - 关闭时需要手动触发保存

  # ===== 角色变量规则 =====
  主角:
    等级:
      type: number
      range: 1~100
      check:
        - 经验值达到阈值时自动提升
        - 升级可能触发特殊事件
        - 影响战斗力和可用技能

    经验值:
      type: number
      range: 0~999999
      check:
        - 每次战斗、完成任务获得经验
        - 升级后经验值重置（多余经验转入下一级）
        - 特殊事件可能奖励大量经验

    当前位置:
      check:
        - 跟随世界.当前地点自动更新
        - 用于特定场景的精确定位

    好感度:
      type: |-
        {
          [角色名: string]: number;  // 0~100
        }
      check:
        - 与每个角色互动时更新
        - 某些全局事件可能影响所有角色好感度
        - 达到特定值可能触发特殊剧情

  角色A:
    好感度:
      range: -100~100
      check:
        - 主要由与该角色的互动影响
        - 全局事件也可能影响（如拯救世界+5好感度）
        - 单次变化±1~5，根据互动内容调整
        - 极端行为可能导致大幅变化（±10~20）

    当前状态:
      check:
        - 跟随好感度和剧情进展自动更新
        - 或根据特殊事件独立设定
        - 描述角色当前的心理/生理状态
        - 影响角色对话和行为

  角色B:
    [同角色A的结构]
```

## 5. 命名规范与约定

### 5.1 全局变量命名规范

#### 顶级命名空间

| 命名空间 | 用途 | 示例 |
|----------|------|------|
| `世界` | 世界状态和时间 | `世界.当前时间`、`世界.当前地点` |
| `时间系统` | 时间相关计算 | `时间系统.游戏天数`、`时间系统.当前时辰` |
| `事件状态` | 事件完成情况 | `事件状态.主线_初遇`、`事件状态.支线_救援` |
| `计数器` | 数值统计 | `计数器.击败_敌人`、`计数器.收集_草药` |
| `设置` | 游戏配置 | `设置.游戏模式`、`设置.音效开关` |

#### 变量名命名规范

**时间相关**：
- `当前时间`：完整的时间字符串
- `当前地点`：具体的场所名称
- `游戏天数`：从1开始的整数
- `当前时辰`：有限状态的枚举
- `经过小时数`：0-24的小数
- `总游戏时长`：累积小时数

**状态相关**：
- `天气`：天气状况字符串
- `季节`：春夏秋冬枚举
- `昼夜`：时间段落枚举

### 5.2 事件命名规范

#### 前缀分类

| 前缀 | 含义 | 示例 |
|------|------|------|
| `主线_` | 主线剧情事件 | `主线_初遇`、`主线_觉醒`、`主线_终章` |
| `支线_` | 支线任务事件 | `支线_救援村民`、`支线_寻找失踪者` |
| `隐藏_` | 隐藏内容/彩蛋 | `隐藏_古老遗迹`、`隐藏_神秘商人` |
| `成就_` | 成就类事件 | `成就_首次击败BOSS`、`成就_完美通关` |
| `收集_` | 收集类事件 | `收集_全套卡牌`、`收集_所有武器` |
| `特殊_` | 特殊机制事件 | `特殊_时间倒流`、`特殊_多重结局` |

#### 命名规则

1. **使用下划线分隔**：`主线_初遇`而不是`主线-初遇`或`主线.初遇`
2. **简洁明确**：`主线_初遇`而不是`主线_第一次相遇`
3. **保持一致**：`支线_救援`而不是`支线_解救`或`支线_拯救`
4. **避免重复**：不同事件使用不同名称

### 5.3 计数器命名规范

## 6. 常见问题解答

### Q1: 如何确保全局变量的类型安全？

**答**：所有全局变量都必须通过Zod定义，使用`z.coerce`进行类型转换，使用`z.transform`进行范围限制：

```javascript
// ✅ 类型安全
游戏天数: z.coerce.number().int().nonnegative(),
经过小时数: z.coerce.number().transform(v => _.clamp(v, 0, 24)),

// ❌ 类型不安全
游戏天数: z.number(),  // 无法处理字符串输入
经过小时数: z.number(),  // 可能超出范围
```

### Q2: 如何防止全局变量被意外修改？

**答**：使用`.strict()`确保只接受定义的字段：

```javascript
// ✅ 严格模式
世界: z.object({
  当前时间: z.string(),
  当前地点: z.string()
}).strict(),  // 禁止额外字段

// ❌ 宽松模式（不推荐）
世界: z.object({
  当前时间: z.string(),
  当前地点: z.string()
})  // 允许额外字段，可能导致数据混乱
```

### Q3: 全局变量和角色变量的数据存储在哪里？

**答**：所有变量都存储在`stat_data`对象中：

```javascript
{
  "stat_data": {
    // 全局变量
    "世界": { ... },
    "时间系统": { ... },
    "事件状态": { ... },
    "计数器": { ... },

    // 角色变量
    "角色A": { ... },
    "角色B": { ... }
  }
}
```

### Q4: 如何在EJS模板中访问全局变量？

**答**：使用`getvar()`函数：

```ejs
<!-- 访问全局变量 -->
<%_ if (getvar('stat_data.世界.天气') === '暴雨') { _%>
暴雨天气，户外活动变得困难。
<%_ } _%>

<!-- 访问事件状态 -->
<%_ if (getvar('stat_data.事件状态.主线_初遇') === true) { _%>
主线事件"初遇"已完成。
<%_ } _%>

<!-- 访问计数器 -->
<%_ if (getvar('stat_data.计数器.击败_哥布林') >= 5) { _%>
已经击败了5只哥布林！
<%_ } _%>
```

### Q5: 如何在状态栏中显示全局变量？

**答**：使用jQuery和`_.get()`安全访问：

```javascript
function populateCharacterData() {
    const all_variables = getAllVariables();
    const characterData = all_variables.stat_data;

    // 显示世界状态
    $('#当前时间').text(_.get(characterData, '世界.当前时间', 'N/A'));
    $('#当前地点').text(_.get(characterData, '世界.当前地点', 'N/A'));
    $('#天气').text(_.get(characterData, '世界.天气', 'N/A'));

    // 显示时间系统
    $('#游戏天数').text(_.get(characterData, '时间系统.游戏天数', 0));
    $('#当前时辰').text(_.get(characterData, '时间系统.当前时辰', 'N/A'));

    // 显示事件状态
    const events = _.get(characterData, '事件状态', {});
    let eventHtml = '';
    _.forEach(events, (completed, eventName) => {
        const status = completed ? '✅' : '⏳';
        eventHtml += `<div>${status} ${eventName}</div>`;
    });
    $('#事件列表').html(eventHtml);

    // 显示计数器
    const counters = _.get(characterData, '计数器', {});
    let counterHtml = '';
    _.forEach(counters, (count, counterName) => {
        counterHtml += `<div>${counterName}: ${count}</div>`;
    });
    $('#计数器列表').html(counterHtml);
}
```

### Q6: 如何处理复杂的跨角色交互？

**答**：使用全局变量作为桥梁：

```javascript
// 角色A救了一个村庄
{
  "op": "replace", "path": "/事件状态/支线_救援村民", "value": true },
  { "op": "replace", "path": "/计数器/完成_支线任务", "value": 1 },
  { "op": "replace", "path": "/角色B/好感度", "value": 85 }  // 角色B对主角好感度+20
}
```

### Q7: 如何实现定时事件或延迟触发？

**答**：使用游戏天数和计数器：

```javascript
// 3天后触发特殊事件
{
  "op": "add", "path": "/事件状态/-", "value": { "事件名": "特殊_三日之约", "触发天数": 4 } }
}
```

然后在EJS中检查：

```ejs
<%_ if (getvar('stat_data.时间系统.游戏天数') >= 4 && !getvar('stat_data.事件状态.特殊_三日之约')) { _%>
特殊事件"三日之约"触发！
<%_ } _%>
```

### Q8: 如何处理数据冲突（多个地方同时修改同一变量）？

**答**：Zod会自动处理并发问题，最后一次操作生效。建议：

1. **明确修改权限**：在更新规则中说明谁能修改什么
2. **避免循环依赖**：A依赖B，B依赖A可能导致问题
3. **使用事务性更新**：一次性更新所有相关变量

## 7. 最佳实践

### 7.1 Schema设计最佳实践

#### 1. 优先使用z.coerce.number()

```javascript
// ✅ 推荐：自动转换
hp: z.coerce.number().transform(v => _.clamp(v, 0, 100))

// ❌ 避免：无法处理字符串
hp: z.number()
```

#### 2. 优先使用z.record()而非z.array()

```javascript
// ✅ 推荐：对象结构，便于访问
技能: z.record(
  z.coerce.number().transform(v => _.clamp(v, 0, 10))
)

// ❌ 避免：数组结构，难以精确定位
技能: z.array(z.object({
  名称: z.string(),
  等级: z.number()
}))
```

#### 3. 使用z.transform()进行范围限制

```javascript
// ✅ 推荐：自动限制范围
好感度: z.coerce.number().transform(v => _.clamp(v, -100, 100))

// ❌ 避免：抛出错误而非修正
好感度: z.coerce.number().min(-100).max(100)
```

#### 4. 使用z.prefault()提供默认值

```javascript
// ✅ 推荐：使用prefault
物品栏: z.record(z.string(), z.any()).prefault({})

// ❌ 避免：使用default（可能导致重复添加）
物品栏: z.record(z.string(), z.any()).default({})
```

### 7.2 JSON Patch操作最佳实践

#### 1. 使用标准路径格式

```javascript
// ✅ 推荐：JSON Pointer格式
{ "op": "replace", "path": "/世界/当前时间", "value": "新时间" }

// ❌ 避免：点分隔符
{ "op": "replace", "path": "世界.当前时间", "value": "新时间" }
```

#### 2. 数组操作使用特殊索引

```javascript
// ✅ 推荐：添加到末尾
{ "op": "add", "path": "/inventory/-", "value": "新物品" }

// ✅ 推荐：删除指定索引
{ "op": "remove", "path": "/inventory/0" }
```

#### 3. 批量操作使用数组

```javascript
// ✅ 推荐：一次性更新多个变量
[
  { "op": "replace", "path": "/世界/当前时间", "value": "新时间" },
  { "op": "replace", "path": "/时间系统/经过小时数", "value": 12 },
  { "op": "replace", "path": "/计数器/交谈_次数", "value": 1 }
]
```

### 7.3 变量组织最佳实践

#### 1. 分层组织

```javascript
// ✅ 推荐：清晰的层次结构
世界: {
  当前时间: "",
  当前地点: "",
  天气: ""
},
时间系统: {
  游戏天数: 0,
  当前时辰: ""
}
```

#### 2. 一致性命名

```javascript
// ✅ 推荐：一致的命名风格
击败_哥布林: 0,
击败_狼群: 0,
击败_BOSS: 0

// ❌ 避免：混乱的命名
kill_goblin: 0,
击败狼: 0,
boss_kills: 0
```

#### 3. 避免过度嵌套

```javascript
// ✅ 推荐：扁平化结构
事件状态: {
  主线_初遇: false,
  主线_觉醒: false
}

// ❌ 避免：深层嵌套
事件状态: {
  主线: {
    初遇: false,
    觉醒: false
  }
}
```

### 7.4 性能优化最佳实践

#### 1. 避免频繁更新

```javascript

[
  { "op": "replace", "path": "/时间系统/经过小时数", "value": 12 },
```

### 案例1：完整的时间推进系统

#### 需求
- 每次交互推进1-3小时
- 满24小时+1游戏天数
- 根据时间自动更新昼夜和时辰
- 夜晚可能触发特殊事件

#### 实现

**Schema定义**：
```javascript
时间系统: z.object({
  游戏天数: z.coerce.number().int().nonnegative(),
  当前时辰: z.enum(["深夜", "凌晨", "清晨", "上午", "正午", "下午", "傍晚", "夜晚"]),
  经过小时数: z.coerce.number().transform(v => _.clamp(v, 0, 24))
}).strict()
```

**更新规则**：
```yaml
时间系统:
  经过小时数:
    range: 0~24
    check:
      - 每次交互推进1~3小时
      - 满24自动归零，+1游戏天数
      - 影响角色作息和可用行动
```

**JSON Patch示例**：
```javascript
// 推进2小时
[
  { "op": "replace", "path": "/时间系统/经过小时数", "value": 12 }
]
```

**EJS动态内容**：

## 📚 总结

### 核心要点

1. **顶层设计**：全局变量直接定义在Schema顶层，避免嵌套
2. **类型安全**：所有变量都通过Zod验证和转换
3. **清晰命名**：使用明确的命名规范和前缀
4. **统一访问**：通过`getAllVariables()`统一获取
5. **标准更新**：使用JSON Patch进行修改

### 优势

- ✅ **共享性**：所有角色和系统共享同一份数据
- ✅ **类型安全**：自动验证、转换和范围限制
- ✅ **标准化**：统一的访问和修改方式
- ✅ **可追踪**：完整的事件和计数器系统
- ✅ **可扩展**：易于添加新的全局变量

### 使用场景

- **时间系统**：游戏时间、昼夜更替、季节变化
- **世界状态**：当前地点、天气、环境
- **事件追踪**：主线进度、支线完成、隐藏内容
- **成就统计**：击败敌人、完成任务、收集物品
- **系统设置**：游戏模式、用户偏好
